## 二、面板结构

```
BottomSheetModal（LOGIN_HEIGHT = 640）
├── 顶部：关闭按钮（右对齐）
├── 上半主区（靠上紧凑，gap 16）
│   ├── 一键登入：本机号码一键登入按钮 + 运营商识别提示
│   ├── 验证码登入：手机号(+86) + 获取验证码 → OTP 6 格 + 登录
│   └── 密码登入：手机号(+86) + 密码 + 登录
│   └── 切换行（随面板变化）
└── 下半区（不变）：其他登录方式分隔线 + 微信 / QQ
```

## 三、切换行各面板形态

| 面板 | 切换行布局 |
| ---- | ---------- |
| 一键登入 | 居中「验证码登入｜密码登入」 |
| 验证码 | 居中「密码登入｜一键登入」 |
| 密码登入 | 两端布局：左侧「验证码登入｜一键登入」，右侧「找回密码」 |

## 四、验证码流程

1. 手机号输入（+86 前缀，11 位有效才可发码）
2. 点击「获取验证码」→ 进入 OTP 阶段，显示「验证码已发送至 138\*\*\*\*xxxx」+ 60s 倒计时重发
3. 6 格分格输入区：透明输入框接收 number-pad 输入，激活格蓝色高亮边框 + 淡蓝底
4. 验证码满 6 位后登录按钮点亮

## 五、校验与禁用逻辑

- 演示码 / 演示密码：`123456`
- 「获取验证码」禁用条件：手机号非 11 位有效
- 「登录」禁用条件：手机号有效且验证码满 6 位 / 密码非空
- 禁用态样式：`rgba(127,127,127,0.55)` 灰底 + 70% 透明度（两按钮共用）
- 一键登入点击即成功（模拟运营商识别）

## 六、遗留

- 找回密码 / 密码重置为演示提示（`Alert`），接真实后端时替换
- 验证码发送为本地模拟（直接提示演示码），接真实后端时替换为短信网关

## 七、键盘交互与遮挡处理

### 1. 登入面板输入不再触发搜索框上移（map-search-bar.tsx）

- **原因**：搜索框监听全局 `keyboardWillShow`，登入面板（Modal 内输入框）弹键盘也会触发上移
- **修复**：
  - `keyboardWillShow` 回调内用 `requestAnimationFrame` 延迟一帧（iOS 键盘通知先于 RN 焦点状态提交），再判断 `isFocused()`，仅搜索框自身聚焦才上移
  - 动画 `duration` 使用键盘事件 `e.duration`，`easing` 用 `Easing.out(Easing.cubic)`（与键盘弹出曲线一致，避免观感"慢半拍"）
  - 键盘收起同理复位

### 1.1 搜索框偶发不上移（map-search-bar.tsx）

- **原因**：iOS 键盘通知与 RN 焦点状态提交的时序偶发不稳定，`requestAnimationFrame` 仅延迟一帧（约 16ms），系统负载高或时序抖动时焦点尚未落定，`isFocused()` 返回 false 即跳过上移
- **修复**：抽出 `moveIfFocused()` 判断函数——首帧（rAF）判断失败时延迟 80ms 兜底重试一次
  - 正常场景：焦点已落定，立即上移，动画仍与键盘同步
  - 偶发场景：80ms 内焦点落定，兜底重试成功，不再跳过
  - 登入面板等其他弹层弹键盘：焦点不在此输入框，两次判断均跳过，不会误上移

### 2. 键盘弹出时上半区不被遮挡（login-sheet.tsx + bottom-sheet-modal.tsx）

- **排查过程**：
  - 原 `KeyboardAvoidingView`（behavior=padding）会把内容顶出固定高度面板而被顶部裁切 → 弃用
  - 尝试"键盘弹出时卡片整体上移"（`BottomSheetModal` 新增 `kbOffset` 位移）→ 体验不佳，已回退
- **最终方案（静态加高）**：移除 KAV 与键盘位移逻辑，面板高度逐级加大 456 → 500 → 560 → 600 → **640**
  - 640 高下键盘弹出（含预测栏约 370pt），上半区可见 270pt，密码面板两端切换行（约 256pt 处）完整露出
  - 下半区（其他登录方式 / 微信 / QQ）在键盘弹出时被遮挡属预期（键盘收起后可见）

### 3. 点击面板空白区域收起键盘（login-sheet.tsx）

- 面板内容外层 `View` 改为 `Pressable`，`onPress={Keyboard.dismiss}`
- 点击输入框与内部按钮不受影响（内层 Pressable 优先消费触摸）
